# حسابات تجريبية لكل اللوحات

لا توجد في الكود أي كلمة مرور. الحسابات التجريبية تُنشأ على **مشروع Supabase للاختبار** بأمر واحد، وتُعرض كلمات مرورها مرة واحدة فقط.

## الخطوات
1. أنشئ مشروع Supabase منفصلًا للاختبار، وطبّق الترحيلات (`supabase db push`).
2. في محرر SQL لمشروع **الاختبار فقط**:
   ```sql
   insert into public.app_flags values ('test_accounts', 'true') on conflict (key) do update set value = 'true';
   ```
   قاعدة البيانات ترفض إنشاء الحسابات التجريبية بدون هذا الإعداد. لا تفعّله في الإنتاج.
3. من جهازك (مفتاح الخدمة من Settings ← API، ولا يُحفظ في المشروع):
   ```bash
   SUPABASE_URL=https://<ref>.supabase.co SUPABASE_SERVICE_ROLE_KEY=… npm run test-accounts -- create
   ```
4. يطبع الأمر جدولًا بالحسابات وكلماتها:

| اللوحة | البريد | ماذا يرى |
|---|---|---|
| الإدارة | `admin@safeer.test` | كل الشاشات. يُطلب تفعيل تطبيق التحقق (TOTP) عند أول دخول |
| المصنع | `factory@safeer.test` | يملك «مصنع تمور الأحساء» (`hasa`) بمنتجاته، موثّق بوثائق تجريبية |
| السفير | `ambassador@safeer.test` | سفير قائد، الكود `TEST-AMB` |
| المشتري | `buyer@safeer.test` | حساب مشترٍ من إندونيسيا |

خيارات: `--domain mycompany.test` و`--password '…'` (12 حرفًا على الأقل، لكلمة موحّدة) و`--factory <id>`.

## إعادة التعيين والحذف
- تشغيل `create` مرة أخرى يعيد تعيين كلمات المرور ولا يكرر الحسابات.
- `npm run test-accounts -- remove` يسحب الأدوار ويفك ربط المصنع ويحذف الحسابات. الحساب الذي له طلبات أو قيود مالية يُوقف دخوله بدل حذفه، حفاظًا على السجل.

## بديل بلا خادم
للمعاينة فقط: `VITE_ENABLE_DEMO=true` ثم `npm run dev`، ثم زر «الدخول التجريبي». يعرض بيانات توضيحية، ولا يكتب في قاعدة البيانات.
